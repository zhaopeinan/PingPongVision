# 动作分析报告界面设计

## 背景

动作分析目前把后端返回的字段直接拼成多行文本。用户需要先阅读字段名，才能知道分析了哪些片段、检测到多少人以及指标是否有效，结果不适合训练复盘。

本次改动只优化动作分析完成后的结果展示，不改变 YOLO-Pose、MediaPipe、身份跟踪或动作分析 API 的数据结构。目标是让教练可以先扫描结论，再展开查看指标和逐帧细节。

## 设计目标

- 首屏先回答“分析了什么、覆盖是否足够、检测到了谁”。
- 用中文标签、单位和视觉层级替代原始 JSON 字段名。
- 在身份无法可靠确认时显示不确定状态，不根据左右位置猜测身份。
- 让两个选手的同类动作指标可以快速横向比较。
- 保留完整逐帧数据作为可展开的技术细节。
- 支持一个原始视频、一个片段和全部片段三种分析来源。

## 方案选择

### 方案 A：字段翻译和分组

将现有文本字段换成中文并按手臂、身体分组。实现成本最低，但结果仍接近数据表，用户仍需要逐项阅读。

### 方案 B：片段列表、选手卡片和对比视图（采用）

顶部提供整体摘要；每个分析片段独立成区；片段内展示选手卡片；同一片段的手臂指标提供对比条；身体指标和原始帧数据通过折叠区域按需查看。

选择理由：不需要后端新增聚合数据，能直接利用现有汇总字段，同时把最常用的训练复盘信息放在默认视图中。两名选手身份不明确时仍可通过跟踪编号区分卡片，但不强制映射为“左侧/右侧”或固定姓名。

### 方案 C：完整遥测仪表盘

增加角度分布图、逐帧时间轴和事件图表。当前后端没有动作事件模型和面向可视化的时间序列聚合，短期内容易产生超出数据可靠性的视觉精度，因此不纳入本次范围。

## 页面结构

### 1. 总览区

报告顶部显示：

- 分析片段数
- 总分析帧数
- 检测到的跟踪对象数
- 平均姿态覆盖率

覆盖率定义为拥有至少一个人体姿态结果的帧数除以分析帧数。若后端没有逐帧结果或总帧数为零，显示“暂无数据”，不显示误导性的 0%。

### 2. 片段报告区

每个 `analysis` 显示一个片段区域，包含：

- 文件名
- 分析帧数和帧率
- 片段姿态覆盖率
- 选手卡片或“未检测到稳定人体姿态”的空状态

片段区使用完整边框和背景层级区分，不使用彩色侧边条。

### 3. 选手指标卡

每个 `person` 卡片显示：

- 身份标签：确认时显示 `player_n`；未确认时显示“身份未确认”。
- 跟踪编号。
- 身份置信度，以百分比和低/中/高状态呈现。
- 跟踪帧数与片段覆盖率。
- 手臂角度指标：左肘、右肘、左肩、右肩，单位为度。

卡片只呈现实际存在且为有限数值的指标。缺失指标显示短空状态，而不是输出 `undefined` 或空字段。

### 4. 选手对比区

当同一片段存在至少两个选手卡片时，显示四项手臂角度的横向对比：

- 每项显示指标中文名称。
- 每个选手显示数值和相对长度条。
- 条形长度只用于比较当前片段中的数值，不表达技术好坏或标准动作范围。
- 未确认身份使用“跟踪 1/跟踪 2”等稳定的中性标签。

只有一个选手或没有有效角度时不显示空的对比组件。

### 5. 可折叠细节

- “身体指标”折叠区显示 `average_body_metrics` 中的有效数值。
- “查看逐帧原始数据”折叠区保留完整 `frames` JSON，使用等宽字体和原始数据提示。

默认折叠，避免技术字段压过训练结论。原始数据仍然可复制和检查。

## 数据映射

后端数据保持不变，前端仅负责展示映射：

| 后端字段 | 展示内容 |
| --- | --- |
| `source` | 片段文件名 |
| `frames_analyzed` | 分析帧数 |
| `fps` | 帧率，单位 fps |
| `persons.length` | 跟踪对象数 |
| `frames[].persons.length > 0` | 姿态覆盖率 |
| `track_id` | 跟踪编号 |
| `identity` | 身份状态 |
| `identity_confidence` | 身份置信度 |
| `frame_count` | 选手跟踪帧数及片段覆盖率 |
| `average_arm_angles` | 手臂角度卡片和对比条 |
| `average_body_metrics` | 身体指标折叠区 |
| `frames` | 逐帧原始数据折叠区 |

指标标签使用显式映射表；未知字段继续显示可读化后的名称，保证后端将来增加指标时不会静默丢失。

## 状态和错误处理

- 没有分析片段：显示“没有可展示的动作分析结果”。
- 片段没有选手：显示“未检测到稳定的人体姿态”，并保留帧数和覆盖率。
- 身份置信度低于 60%：显示“身份未确认”；不显示 `player_n` 作为确定身份。
- 数值缺失、非数字或非有限：不渲染数值，并在对应区域显示“暂无有效数据”。
- 原始帧数据为空：隐藏原始数据折叠项，避免出现空 JSON。
- 文件名和原始数据必须经过 HTML 转义，避免视频文件名或数据内容破坏报告 DOM。

## 响应式和可访问性

- 桌面端两个选手卡片并排；窄容器自动变为单列。
- 对比条在窄屏仍保持指标名、标签和数值不重叠，必要时按选手分行。
- 折叠区使用原生 `details/summary`，支持键盘和屏幕阅读器。
- 颜色不作为唯一状态表达，置信度同时显示文字和百分比。
- 所有动态生成的按钮和折叠标题使用可理解的中文文本。

## 实现边界

- 修改 `pingpong_analyst/static/app.js` 的动作报告渲染和格式化辅助函数。
- 修改 `pingpong_analyst/static/style.css` 的动作报告样式和窄屏适配。
- 不修改动作分析 API、模型加载、结果字段和任务轮询协议。
- 不引入新的前端依赖。

## 验收标准

- 动作分析完成后默认不再显示类似 JSON 的字段串。
- 用户无需阅读英文键名即可理解片段、帧数、覆盖率、身份和角度。
- 两名选手同时存在时可以在同一片段中横向比较手臂角度。
- 无选手、无有效指标和身份未确认状态均有明确显示。
- 原始逐帧结果仍可展开查看。
- `node --check pingpong_analyst/static/app.js` 通过，`git diff --check` 无错误。
- 在桌面和窄屏浏览器中没有文本重叠或横向溢出。

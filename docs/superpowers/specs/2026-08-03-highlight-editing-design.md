# 精彩分段成片编辑器设计

## 背景

当前板数分析完成后，分析页侧栏只显示分段列表，点击分段后通过弹窗播放单个 MP4。用户需要逐个查看多个分段、调整片段边界、选择和排序，再把结果渲染成一个可导出的比赛集锦。

本设计增加一个独立的成片编辑器页面，服务于同一个原始视频的精彩分段。它不改变球追踪或板数分析算法，只接收分析生成的分段结果并提供后处理工作流。

## 目标与范围

### 目标

- 分析完成后可以从分析页进入独立的成片编辑器。
- 逐个预览分析分段，并显示板数、时长和原始时间范围。
- 每个分段可以微调开始和结束时间。
- 分段可以选择、删除和重新排序。
- 编辑状态可以持久化，服务重启后可以从视频库恢复。
- 确认后异步渲染硬切成片，保留原始声音。
- 渲染完成后可以在线预览和下载 MP4。

### 非目标

- 一个项目不混剪多个原始视频。
- 本次不提供转场、字幕、贴纸、配乐、画中画或多轨时间线。
- 本次不改变 TrackNet、球台标定、板数统计或动作分析逻辑。
- 本次不引入第三方完整视频编辑器依赖。

## 方案选择

### 方案 A：独立编辑器、持久化项目和服务端 FFmpeg 渲染（采用）

分析结果创建可恢复项目；独立页面管理预览和编排；服务端使用 FFmpeg 精确裁剪和合并；渲染任务完成后提供最终文件。

优点是符合当前项目的前后端结构，能在 macOS 和 NVIDIA T4 服务器上运行，且可以将编辑状态和渲染结果保存下来。微调时间使用重编码，避免 `stream_copy` 按关键帧切割造成边界不准确。

### 方案 B：前端临时播放列表和一次性拼接

开发成本较低，但刷新页面或服务重启会丢失编排状态，无法满足可恢复项目需求。

### 方案 C：引入完整视频编辑框架

可以扩展更多时间线和特效能力，但增加部署、编码和维护成本，超出硬切比赛集锦的当前范围。

## 用户流程

1. 用户在分析页完成板数分析。
2. 分析任务完成时，后端自动创建一个 `draft` 成片项目，并在分析结果中返回 `project_id`。
3. 分析页保留当前结果，同时展示“进入成片编辑”按钮。用户点击后进入 `/editor/{project_id}`，不会自动打断当前页面。
4. 编辑器默认打开第一个分段，并默认选中所有有效分段。
5. 用户逐个播放分段，调整起止时间，取消误检分段，拖拽或使用上移/下移按钮调整顺序。每次改动自动保存。
6. 用户进入“编排成片”步骤，检查选中列表、总时长和总板数。
7. 用户确认后点击“确认并渲染”。编辑控件锁定，页面轮询渲染进度。
8. 渲染完成后显示最终成片播放器、文件信息和下载按钮。用户也可以返回编辑继续修改并重新渲染。

## 持久化数据模型

项目文件保存于 `data/edit_projects/<project_id>.json`，最终成片保存于 `output/exports/<project_id>.mp4`。项目写入采用临时文件加原子替换。

```json
{
  "project_id": "e6a1c2d4",
  "video_id": "0c42afad",
  "source_filename": "0c42afad_test.mp4",
  "source_storage_name": "0c42afad_test.mp4",
  "status": "draft",
  "created_at": "2026-08-03T16:00:00+08:00",
  "updated_at": "2026-08-03T16:05:00+08:00",
  "segments": [
    {
      "segment_id": "segment-001",
      "analysis_index": 1,
      "clip_filename": "rally_001_b12_4.2s.mp4",
      "detected_start_time": 3.7,
      "detected_end_time": 8.9,
      "clip_start_time": 3.2,
      "clip_end_time": 9.4,
      "edit_start_time": 3.2,
      "edit_end_time": 9.4,
      "board_count": 12,
      "selected": true,
      "order": 1
    }
  ],
  "render": {
    "status": "idle",
    "progress": 0,
    "task_id": null,
    "output_filename": null,
    "duration": null,
    "error": null
  }
}
```

`clip_start_time` 和 `clip_end_time` 使用现有剪辑器的前后缓冲，默认分别为检测时间减/加 0.5 秒，并限制在原视频范围内。`edit_start_time` 和 `edit_end_time` 默认等于这两个值，用户可以在该范围内微调，保证播放器预览和最终渲染使用相同的时间窗口。

`source_filename` 用于页面展示，`source_storage_name` 用于服务端在视频库中重新定位实际文件。现有视频库重启后会重新生成内存 `video_id`，因此不能只依赖 `video_id` 做恢复。客户端只接收项目 ID、展示文件名和分段元数据，不接收服务器真实路径。服务端优先根据当前视频注册项映射 `source_storage_name`，再根据安全文件名解析原始视频，所有文件名和项目 ID 都要经过路径边界校验。

## 后端 API

### 项目读取和保存

- `GET /api/edit-projects?video_id=<video_id>`
  - 返回该视频可恢复的项目列表，按更新时间倒序。
- `GET /api/edit-projects/<project_id>`
  - 返回项目及分段数据。
- `PATCH /api/edit-projects/<project_id>`
  - 更新分段的 `selected`、`order`、`edit_start_time` 和 `edit_end_time`。
  - 服务端重新排序并执行时间范围校验后再持久化。

### 渲染和导出

- `POST /api/edit-projects/<project_id>/render`
  - 校验至少选择一个分段、起止时间合法且项目未在渲染。
  - 创建或重置渲染任务，返回 `project_id` 和 `status=rendering`。
- `GET /api/edit-projects/<project_id>/render`
  - 返回 `status`、`progress`、`message`、`output_filename`、`duration` 和 `error`。
- `GET /api/edit-projects/<project_id>/export`
  - 仅在渲染完成且文件存在时返回 MP4 文件，否则返回明确的 409/404 错误。

分析任务完成时自动创建项目；创建操作应保持幂等，重复读取同一个分析任务不会重复生成项目文件。为支持历史分析结果，分析页若没有 `project_id` 可以调用一个兼容的项目创建入口，由服务端从已有分析结果创建草稿。

## 独立编辑器页面

页面入口为 `/editor/<project_id>`，使用独立的 `editor.html` 和 `editor.js`，复用现有颜色、字体、按钮和视频播放器样式。

### 浏览分段

- 左侧使用大播放器播放当前分段。
- 显示当前序号、板数、时长和原视频时间。
- 提供播放/暂停、播放速度、上一段和下一段操作。
- 右侧显示所有分段卡片，点击卡片切换当前分段。
- 卡片显示分析序号、板数、时长和选中状态。
- 默认选中所有有效分段；取消选择不会删除分段，可以随时恢复。
- 起止时间用双端范围控件和数字输入同步编辑，输入值始终限制在 `clip_start_time` 与 `clip_end_time` 内。

### 编排成片

- 只显示已选分段，支持拖拽排序。
- 每个分段提供上移、下移和移除操作，移动端和键盘操作不依赖拖拽。
- 左侧仍保留当前分段预览和起止时间编辑。
- 顶部显示选中分段数、预计总时长和总板数。
- “保存项目”状态显示最近一次自动保存时间；保存失败时显示错误并允许重试。

### 渲染导出

- 显示最终顺序的只读摘要。
- 点击确认后锁定编辑控件，显示阶段文字和 0-100% 进度。
- 渲染完成后显示最终 MP4 播放器、总时长、分段数和文件大小。
- 提供下载按钮和“返回编辑”按钮。
- 失败时保留用户的项目编排，显示错误摘要和“重新渲染”。

## FFmpeg 渲染

渲染使用原始视频作为输入，按项目中 `order` 排序的选中分段构造视频和音频过滤链：

- 视频链使用 `trim`、`setpts=PTS-STARTPTS`。
- 有音频时使用 `atrim`、`asetpts=PTS-STARTPTS`。
- 使用 `concat` 过滤器完成硬切合并。
- 无音频时只映射视频输出，不生成虚拟音轨。
- 输出默认使用 H.264/AAC、`+faststart` 和项目配置的质量参数。
- macOS 和服务器按可用编码器自动选择，硬件编码不可用时使用 `libx264`。

渲染任务使用 `Popen` 和 FFmpeg `-progress pipe:1` 读取输出时间，按选中分段总时长计算进度并原子更新项目状态。每个进程实例同时只运行一个成片渲染任务，避免与分析任务争抢显存、CPU 和磁盘 IO。

## 状态和错误处理

- 项目不存在：返回 404。
- 原始视频不存在或已移动：返回 409，并提示重新选择视频。
- 没有选中分段：拒绝渲染，提示至少选择一个分段。
- 起止时间不合法或超出范围：拒绝保存和渲染，指出具体分段。
- FFmpeg 不存在：项目变为 `failed`，保留草稿并提示安装/配置 FFmpeg。
- FFmpeg 非零退出：保存末尾错误摘要，不删除草稿。
- 渲染中的重复请求：返回当前任务状态，不启动第二个进程。
- 页面轮询失败：保留最后状态并显示重试入口，不清空用户编排。

## 实现边界

- 新增项目存储和渲染模块，避免把 JSON 操作和 FFmpeg 命令全部堆进 `api.py`。
- 修改分析任务完成逻辑，为结果生成项目并返回 `project_id`。
- 新增项目相关 API 和独立编辑器静态页面。
- 修改分析页，在结果完成后显示“进入成片编辑”入口。
- 复用现有单段剪辑播放接口作为分段预览；最终渲染使用原视频和项目时间范围。
- 不新增前端框架和第三方视频编辑依赖。

## 测试和验收

### 后端测试

- 项目创建、读取、更新、排序和原子写入。
- 项目恢复和视频 ID 过滤。
- 时间范围、空选择、重复渲染和路径边界校验。
- 有音频/无音频两种 FFmpeg 命令构造。
- FFmpeg 不存在、超时、非零退出和进度解析。
- 渲染完成后的导出权限和文件不存在处理。

### 前端验证

- 分析完成后可以打开独立编辑器。
- 分段上一段/下一段、播放、选择和微调可用。
- 拖拽排序和按钮排序结果一致，并自动保存。
- 刷新编辑器后项目状态和排序恢复。
- 渲染中进度、锁定状态、完成播放器、失败重试和下载入口正确。
- 桌面和窄屏布局无文本重叠或横向溢出。
